# Wafer 面内傾向の異常検知 実データ検証アプリ

模擬データで行った検証（[技術レポート](../reports/technical_report.md)）を、**実データ**で行うためのアプリです。
Alignment・Overlay の計測テーブル（Excel・CSV）を読み込み、画面で設定を選ぶと、
M3S・多項式係数 SPC・Mahalanobis 距離・PCA T²／SPE・GPR 残差・EWMA・CUSUM・OR 統合を
**同じ誤報率にそろえて**比べた結果を表示します。Mac と Windows の両方で動きます。

- 計算の中身は、検証と同じコード（`src/monitoring/` など）をそのまま使います。
- データはこのパソコンの中だけで処理し、インターネットには送りません。
- 画面・メッセージ・保存するファイルはすべて日本語です。

## できること

| 手順 | 画面 | 内容 |
|---|---|---|
| 1 | データ | Excel（.xlsx・.xlsm）か CSV を読み込み、列を対応づけて、未測定・重複・有効半径の外を整理する |
| 2 | 設定 | 正常期間（学習・校正）、誤報率、監視手法、経時変化の監視、異常の注入試験を選ぶ |
| 3 | 結果 | 要点、手法ごとの管理図、警報の一覧、計測ごとの判定、Wafer マップ、注入試験の結果を見る。Excel・CSV・図に保存する |

実データには「どの Wafer が異常か」の正解がふつうはありません。そこで次の3つで比べます。

1. **実データの判定**：正常期間で決めた管理限界を、それより後の計測に当てて、どの手法がどの計測で警報を出すかを見る（M3S では警報が出ず、ほかの手法で警報が出た計測も一覧にする）
2. **既知の異常との照合（任意）**：異常と分かっている Wafer の印（ラベル）の列があれば、手法ごとの検出数・ROC-AUC を出す
3. **異常の注入試験**：校正期間の正常 Wafer に、検証と同じ形の異常（Radial・局所・単一 Shot など）を足して、同じ誤報率で検出率・検出までの枚数を比べる（正常のばらつきは実データ、異常は検証と同じ形）

### まず練習用のデータで試す

メニューの［ヘルプ］→［練習用の模擬データを作る…］で、検証と同じ作り方の模擬データ（実データではない）を作れます。
後半に 1 Wafer の異常4枚（列「既知の異常」が 1）と、ゆっくり増える局所変形が入っています。入れた異常の一覧も同じフォルダに保存されます。

## データの形

1行が1つの Mark の計測で、次の列がある表です（ユーザーの Overlay計測ルールの標準の項目名）。
同じ名前の列は自動で対応づけます。名前が違うときは「列の対応づけ」で選び直してください。

| 項目名 | 意味 | 単位 | 必須 |
|---|---|---|---|
| `Wafer` | Wafer の ID | 文字列 | 必須 |
| `DateTime` | 計測日時（時間の順番に使う） | 日時 | |
| `shotNo` | Shot 番号 | 整数 | |
| `Direction` | Scan 方向（1・2） | コード | |
| `Xmm`・`Ymm` | Shot 中心の座標（Wafer 中心が原点） | mm | 必須 |
| `Radius` | Shot 中心の半径（確認だけに使う） | mm | |
| `markNo` | Shot 内の Mark 番号 | 整数 | |
| `markXmm`・`markYmm` | Shot 中心から見た Mark の座標 | mm | 必須 |
| `measX`・`measY` | X・Y の計測値 | nm（µm も選べる） | 必須 |
| `StsX`・`StsY` | 状態（0 = 有効、−1 = 未測定） | コード | |

前処理（「データを確認する」で行う）：

- X には `StsX = 0` の `measX`、Y には `StsY = 0` の `measY` だけを使います。未測定（−1）などは**欠測**にし、ゼロとしては扱いません
- 解析座標は `x = Xmm + markXmm`、`y = Ymm + markYmm`。半径が有効半径（既定 150 mm）**より小さい**点だけを使います
- `Wafer`・`DateTime`・座標が同じ行は重複とみなし、X・Y をそれぞれ平均します
- `Radius` があれば、`Xmm`・`Ymm` からの計算値と合っているかを確かめます
- 1回の計測（Wafer × 日時）を1件とし、日時の順（同じ日時の中では Wafer ID の自然な順）に並べます
- 製品・工程・装置などが混ざっているときは「絞り込み」で残す値を選びます

## 設定の考え方

既定の値は模擬データの検証と同じです。分からない項目はそのままで構いません。

| 項目 | 既定 | 説明 |
|---|---|---|
| 正常期間 | 先頭から 50% | 異常がないと考えられる期間。この中の前半（既定 50%）で正常のモデルを学習し、後半（校正）で管理限界を決める。正常期間より後が評価期間 |
| 共通の計測点 | 正常期間の 90% 以上で計測できた点 | すべての手法で同じ点を使う。欠けが 20% を超える計測は除き、残りの欠けは正常のモデルで補う（補った値は M3S には使わない） |
| 誤報率 | 1% | 正常の Wafer で警報が出る割合。すべての手法をこの値にそろえる。**校正の件数 × 誤報率 が 5 件以上**あると安定（1% なら校正 500 件） |
| 1 Wafer の手法 | M3S・係数SPC 4次・Mahalanobis 4・5次・PCA（計測値・99%）・GPR（RBF・全体） | 検証の系統別の代表と、推奨の OR 統合に使う手法 |
| OR 統合 | M3S・Mahalanobis 4次・PCA T²・SPE・GPR | どれか1つでも警報なら警報。統合したあとの誤報率を上の値にそろえる |
| 経時変化の監視 | 検証の Phase 2 と同じ6手法 × Shewhart・EWMA・CUSUM | 管理限界は、正常時に最初の誤報が出るまでの平均の枚数 **ARL₀ = 370 枚**にそろえる。λ・k は検証の予備評価で選ばれた値 |
| 注入試験（1 Wafer） | B1〜B5・B7〜B10、1・2・4・8σ_dir、各 500 回 | σ_dir：異常の形の向きでの正常 Wafer のばらつき。B6 は模擬データの係数の相関を使う形なので行わない。B8 は Direction の列が必要 |
| 注入試験（経時変化） | 低次・高次・Radial・局所、Step、0.5・1・2σ_dir、100 系列 | 変化の前に 100 枚、変化の後に 100 枚を見る |

## 結果の見方

| 画面 | 見るところ |
|---|---|
| 概要 | 要点（件数、警報の数、注入試験で一番よかった手法など）と注意。手法ごとの管理限界・校正の警報率（誤報率以下になる）・評価の警報数 |
| 管理図 | 手法ごとのスコアの時間変化。灰色＝学習、水色＝校正、白＝評価。赤い × が警報、▼ がラベルで異常の計測 |
| 警報の一覧 | 手法 × 計測で、警報が出たところに黒い印 |
| 判定一覧 | 計測ごとの判定。「M3S は警報なし・ほかで警報あり」で絞り込める。行をダブルクリックすると Wafer マップへ |
| Wafer マップ | その計測の面内の矢印（計測値、正常時の平均との差、PCA で表せない成分、GPR の残差）と、全手法の判定 |
| 経時変化の管理限界 | ARL₀ にそろえた管理限界、校正期間での実際の警報数（目安は 件数 ÷ ARL₀）、評価期間で最初の警報 |
| ラベルとの照合 | 既知の異常の検出数・検出率、ラベルのない計測での警報率、ROC-AUC |
| 注入試験 | 異常の形・大きさごとの検出率（1 Wafer）と、気づくまでの枚数 RMST（経時変化。未検出は観測した枚数として数える） |

［結果を保存…］で選んだフォルダの中に `検証結果_年月日-時分秒` を作り、次を保存します。

- `検証結果.xlsx`：すべての表（シートごと。値はアプリで計算した結果で、数式ではない）
- `CSV/`：同じ表の CSV（UTF-8・BOM 付き）
- `図/`：手法ごとの管理図、警報の一覧、注入試験の図（PNG）
- `設定.json`：このときの設定（［ファイル］→［設定を読み込む…］で同じ設定に戻せる）

## 注意事項

- **実データの結果を含むファイルは、社外のサービスや公開の場所に置かないでください。** このリポジトリは公開されているので、実データや結果をリポジトリのフォルダに保存しないでください
- 正常期間に異常が混じると、その異常を「正常」として学習してしまいます。正常期間は、工程に問題がなかったと分かっている期間にしてください
- 校正の件数が少ないと管理限界が不安定になります。画面と結果の「注意」に、件数が足りないことと目安が出ます。経時変化では、校正の件数が ARL₀ より少ないと Shewhart の管理限界が校正期間の最大値になり、ほかの検出器より警報が出にくい側に偏ります
- 経時変化の管理限界は、校正期間の Wafer をブロック（既定 25 枚＝1 Lot）単位で並べ替えた長い系列で決めます。ブロックより長い周期のゆっくりした変動は再現されないので、実際の誤報はこれより多くなることがあります（校正期間の実際の警報数で確かめられます）
- 実データの系列では、警報が出たらその検出器の統計量を最初からやり直します（ARL₀ の考え方に合わせるため）。注入試験では、検証と同じく、やり直さずに最初の警報までの枚数を数えます
- 欠けた点は正常のモデル（PPCA）で補うので、欠けた点にある異常は見えません。補った値の数は判定一覧と Wafer マップに出ます
- 1 Wafer の点が多い（1500 点を超える）と GPR は使えません。点の数が少なく多項式の係数を決められない次数も使えません（理由が結果の「注意」に出ます）

## 困ったとき

- エラーのときは「何が起きたか・理由・対処」が画面に出ます
- 予期しないエラーのときは、ログ（ホームフォルダの `.wafer_monitor_validator/log.txt`。［ヘルプ］→［ログのフォルダを開く］）に内容が残ります。ログには計測値は含まれません
- 大きな Excel は読み込みに時間がかかります（進み具合が下に出ます）。数十万行を超えるときは CSV にすると速くなります
- 計算は［中止］（または Esc キー）で止められます

### 実行ファイルを作る

PyInstaller は、作った OS 用の実行ファイルしか作れません。Windows 用は Windows で、Mac 用は Mac で作ります。

| | 手順 | できるもの |
|---|---|---|
| Windows | `build_windows.bat` をダブルクリック | `dist\WaferMonitorValidator\`（フォルダごと配る） |
| Mac | `build_mac.command` をダブルクリック | `dist/WaferMonitorValidator.app` |

どちらも、専用の環境（`.venv-build`）を作り、テストを通してから作り、できた実行ファイルで自己診断をします。
GitHub の Pull Request では、同じことを Windows と Mac の両方で自動で行います（`.github/workflows/realdata-app.yml`）。
